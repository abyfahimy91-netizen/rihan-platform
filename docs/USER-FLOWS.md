## ۲. مسیرهای مشتری

### C1: خرید مشتری آشنا (دایره اول و دوم)

**پرسونا:** P1 (مریم)، P2 (علی) | **اولویت:** Must Have | **زمان:** ۳-۵ دقیقه

    ▶ ورود به سایت (لینک پیامک / تلگرام / معرفی شفاهی)
    │
    ├─ صفحه اصلی: بنر + محصولات منتخب + داستان کوتاه ریهان
    │
    ├─ انتخاب محصول → صفحه جزئیات
    │  ├─ عکس‌ها (گالری) + داستان محصول
    │  ├─ قیمت (تومان) + موجودی
    │  └─ دکمه «افزودن به سفارش»
    │
    ├─ سبد سفارش: لیست + تغییر تعداد + جمع کل
    │  └─ دکمه «ادامه و ثبت سفارش»
    │
    ├─ فرم سفارش (چندمرحله‌ای)
    │  ├─ ۱: موبایل + OTP (یا تشخیص دستگاه به‌خاطر سپرده‌شده)
    │  │  ⚠ شماره نامعتبر → پیام راهنما
    │  │  ◇ کاربر مهمان؟ → بدون ساخت حساب ادامه دهد
    │  ├─ ۲: نام، آدرس، کد پستی ⚠ فیلد خالی
    │  ├─ ۳: روش ارسال (پست / تیپاکس / باربری)
    │  ├─ ۴: پرداخت (کارت‌به‌کارت) → نمایش شماره کارت
    │  └─ ۵: تأیید نهایی + ثبت
    │
    ├─ صفحه تأیید: شماره سفارش + شماره کارت + آپلود رسید
    │
    └─ ■ پیام: «سفارش ثبت شد. پس از تأیید اطلاع‌رسانی می‌شود.»

    └─ ■ تأیید + لینک پیگیری + شماره پشتیبانی

## ۵. مسیرهای خطا و بازیابی

### E1: خطاهای عمومی

    ⚠ ۴۰۴ → پیام دوستانه + پیشنهاد صفحات + دکمه خانه
    ⚠ ۵۰۰ → «مشکلی پیش آمد» + تلاش مجدد + شماره پشتیبانی
    ⚠ قطع اینترنت → ذخیره خودکار فرم + بازیابی پس از اتصال

### E2: بازیابی دسترسی (دستگاه جدید / جلسه منقضی)

    ▶ ورود از دستگاه جدید یا پس از ۳۰ روز
    │
    ├─ مرحله ۱: ورود شماره موبایل
    │  └─ اعتبارسنجی زنده (۱۱ رقم، ۰۹)
    │
    ├─ مرحله ۲: OTP (Kavenegar Verify)
    │  ├─ ۶ رقم — Auto-fill — تایمر ۹۰ ثانیه
    │  ├─ حداکثر ۳ تلاش → OTP جدید
    │  └─ ⚠ شماره ثبت‌نشده → ثبت‌نام خودکار
    │
    ├─ مرحله ۳: ورود موفق
    │  ├─ ◇ ثبت دستگاه جدید؟ → بله → ۳۰ روز بدون OTP
    │  └─ لاگ: دستگاه جدید + زمان + IP
    │
    └─ ■ ورود موفق — دستگاه به‌خاطر سپرده شد

    نکته: «فراموشی رمز» معنی ندارد (رمز اجباری نیست)
    اگر کاربر رمز اختیاری تعریف کرده و فراموش کرده:
    OTP → ورود → تغییر رمز در تنظیمات حساب

### R1: بازیابی سبد رها شده (Cart Recovery)

**پرسونا:** همه مشتریان | **اولویت:** Should Have | **زمان:** خودکار

    ▶ کاربر سبد را رها کرده (۳۰ دقیقه غیرفعال در مرحله ۲ یا بعد)
    │
    ├─ سیستم: ذخیره سبد در abandoned_carts
    │
    ├─ ◇ ۱ ساعت گذشته؟
    │  ├─ بله + موبایل داریم → ارسال SMS یادآوری ملایم
    │  └─ خیر → ادامه
    │
    ├─ ◇ ۲۴ ساعت گذشته؟
    │  ├─ بله + ایمیل داریم → ارسال Email با خلاصه سبد
    │  └─ خیر → ادامه
    │
    ├─ ◇ ۷۲ ساعت گذشته؟
    │  ├─ بله + حاشیه اجازه می‌دهد → SMS با پیشنهاد کوچک
    │  └─ خیر → ادامه
    │
    ├─ ◇ کاربر روی لینک کلیک کرد؟
    │  ├─ بله → auto-restore سبد + ادامه خرید
    │  │  └─ ◇ سفارش تکمیل شد؟
    │  │     ├─ بله → ثبت recovered_at + لاگ
    │  │     └─ خیر → رها شده مجدد
    │  └─ خیر → ادامه
    │
    ├─ ◇ کاربر لغو کرد (unsubscribe)؟
    │  ├─ بله → دیگر پیام ارسال نشود
    │  └─ خیر → ادامه
    │
    └─ ■ پایان (یا بازیابی شد یا لغو شد)

**قوانین (Vision Guard):**
- حداکثر ۳ پیام در ۷ روز
- هرگز فوریت ساختگی نیست
- هرگز موجودی ساختگی نیست
- احترام به حریم خصوصی

## E3: مسیر مدیریت موجودی (Inventory Management)

**پرسوناهای هدف:** P4 (عبدالحسین), P5 (فاطمه), P7 (مولا)
**ماژول‌های مرتبط:** M1 (کاتالوگ), M6 (مالی)
**سند مرجع:** docs/INVENTORY-FLOW.md (D-045)

### مسیر اصلی: ثبت موجودی دستی

1. ادمین یا تأمین‌کننده وارد پنل می‌شود
2. روی «مدیریت موجودی» کلیک می‌کند
3. محصول مورد نظر را انتخاب می‌کند
4. موجودی جدید را وارد می‌کند (عدد + واحد)
5. توضیح اختیاری را وارد می‌کند (مثلاً: خرید از مولا)
6. روی «ثبت موجودی» کلیک می‌کند
7. سیستم موجودی را ذخیره می‌کند و لاگ ثبت می‌کند
8. اگر موجودی کم شده باشد، هشدار نمایش داده می‌شود
9. پیام موفقیت: «موجودی با موفقیت ثبت شد»

### مسیر فرعی: هشدار موجودی کم

1. سیستم به‌صورت خودکار هر ساعت موجودی را بررسی می‌کند
2. اگر موجودی ≤ آستانه هشدار باشد، هشدار فعال می‌شود
3. نمایش در داشبورد ادمین: آیکون قرمز + متن «N محصول رو به اتمام»
4. ادمین روی هشدار کلیک می‌کند
5. لیست محصولات رو به اتمام با جزئیات نمایش داده می‌شود
6. ادمین می‌تواند مستقیم به صفحه ثبت موجودی برود

### مسیر فرعی: بررسی موجودی هنگام سفارش

1. مشتری محصول را به سبد اضافه می‌کند
2. سیستم موجودی لحظه‌ای را بررسی می‌کند
3. اگر موجودی کافی باشد: اجازه افزودن + نمایش «فقط X واحد موجود است»
4. اگر موجودی ناکافی باشد: جلوگیری + پیام خطا
5. مشتری فرم سفارش را پر می‌کند و «ثبت سفارش» می‌زند
6. سیستم موجودی را رزرو می‌کند (۲۴ ساعت)
7. پس از تأیید ادمین: موجودی واقعی کم می‌شود
8. در صورت لغو یا مرجوعی: موجودی خودکار بازگردانده می‌شود

### نکات کلیدی

- موجودی هر محصول مستقل است
- رزرو فقط از لحظه ثبت سفارش شروع می‌شود (نه افزودن به سبد)
- سیستم هرگز موجودی را حدس نمی‌زند
- تمام تغییرات لاگ می‌شوند

## E4: مسیر قیمت‌گذاری و ارسال (Pricing & Shipping Flow)

**پرسوناهای هدف:** P1, P2, P3 (مشتریان), P4, P5 (مدیران خانواده)
**ماژول‌های مرتبط:** M1 (کاتالوگ), M2 (فرم سفارش), M6 (مالی)
**سند مرجع:** docs/SHIPPING-POLICY.md (D-046)

### مسیر اصلی: مشاهده قیمت نهایی

1. مشتری وارد صفحه محصول می‌شود
2. قیمت نهایی (شامل هزینه ارسال) را می‌بیند
3. پیام «شامل هزینه ارسال» نمایش داده می‌شود
4. مشتری تصمیم به خرید می‌گیرد

### مسیر فرعی: سفارش چندمبدأ

1. مشتری چند محصول از مبدأهای مختلف به سبد اضافه می‌کند
2. در صفحه سبد، شفاف‌سازی ملایم نمایش داده می‌شود:
   «ارسال از مبدأهای مختلف انجام می‌شود»
3. جمع کل به‌صورت واضح نمایش داده می‌شود
4. هیچ محاسبه پیچیده‌ای برای مشتری نمایش داده نمی‌شود

### مسیر فرعی: مناطق دورافتاده

1. مشتری آدرس خود را وارد می‌کند
2. سیستم منطقه را شناسایی می‌کند
3. اگر منطقه دورافتاده باشد، پیام ملایم نمایش داده می‌شود:
   «ارسال به منطقه شما ممکن است کمی بیشتر طول بکشد»
4. مشتری مجبور به تماس قبل از ثبت سفارش نیست
5. ادمین پس از ثبت سفارش، در صورت نیاز، با مشتری تماس می‌گیرد

### مسیر فرعی: مدیریت پشت صحنه (ادمین)

1. ادمین وارد پنل مالی می‌شود
2. سفارش را انتخاب می‌کند
3. جزئیات کامل را می‌بیند:
   - قیمت فروش مشتری
   - هزینه تأمین
   - هزینه واقعی ارسال
   - سود واقعی
   - حاشیه واقعی
4. ادمین می‌تواند تنظیمات را تغییر دهد:
   - سهم متوسط ارسال
   - حاشیه هدف
   - روش گرد کردن

### نکات کلیدی

- قیمت نمایش‌داده‌شده به مشتری، قیمت تمام‌شده است
- هزینه واقعی ارسال فقط در پنل ادمین دیده می‌شود
- مشتری در هیچ مرحله‌ای با محاسبه جداگانه مواجه نمی‌شود
- تمام تصمیمات مطابق D-046 است

## E5: مسیر مدیریت خطا و بازیابی (Error Handling & Recovery)

**پرسوناهای هدف:** P1, P2, P3 (مشتریان), P4, P5 (مدیران خانواده), P7 (تأمین‌کننده)
**ماژول‌های مرتبط:** M2 (فرم سفارش), M10 (احراز هویت), M11 (پرداخت)
**سند مرجع:** docs/ERROR-HANDLING.md (D-047)

### اصل بنیادین

> هیچ مشتری نباید در برابر خطا تنها بماند.
> هر خطا با پیام واضح، راه‌حل مشخص و مسیر بازگشت ساده همراه است.

### مسیر اصلی: بازیابی پس از قطع اینترنت

1. مشتری در حال پر کردن فرم سفارش است
2. اینترنت قطع می‌شود
3. سیستم پیام می‌دهد: «اتصال اینترنت قطع شد. اطلاعات شما ذخیره شده است.»
4. پیش‌نویس به مدت ۲۴ ساعت در localStorage نگهداری می‌شود
5. با بازگشت اینترنت، فرم از آخرین مرحله ادامه می‌یابد
6. اگر کاربر بعداً برگشت: «خوش آمدید! ادامه سفارش نیمه‌تمام؟»

### مسیر اصلی: بازیابی پس از OTP ناموفق

1. مشتری شماره موبایل را وارد می‌کند
2. OTP ارسال می‌شود
3. اگر OTP نیامد (پس از ۶۰ ثانیه): دکمه «کد نیامد؟» ظاهر می‌شود
4. مشتری یکی از گزینه‌ها را انتخاب می‌کند:
   - ارسال مجدد کد
   - بررسی پوشه اسپم
   - تماس با پشتیبانی
5. حداکثر ۳ بار ارسال مجدد مجاز است

### مسیر اصلی: بازیابی پس از رد رسید

1. مشتری عکس رسید را آپلود می‌کند
2. ادمین رسید را رد می‌کند (با ذکر دلیل)
3. پیامک به مشتری: «سفارش #۱۲۳۴ نیاز به اصلاح دارد.» + لینک مستقیم
4. مشتری وارد سایت می‌شود
5. گزینه‌ها: آپلود عکس جدید / لغو سفارش / تماس با پشتیبانی

### مسیر اصلی: بازیابی پس از تأخیر تأمین‌کننده

1. سفارش ثبت می‌شود
2. روز ۲: هشدار به ادمین در داشبورد
3. روز ۳: پیامک ملایم به مشتری + پیامک به تأمین‌کننده
4. روز ۵: هشدار جدی به ادمین
5. روز ۷: ادمین تصمیم می‌گیرد (واگذاری / ارسال مستقیم / لغو)

### مسیر اصلی: بازیابی پس از موجودی تمام شدن

1. مشتری محصول را به سبد اضافه می‌کند
2. قبل از ثبت سفارش، موجودی توسط شخص دیگری رزرو می‌شود
3. در لحظه ثبت سفارش، پیام: «متأسفانه موجودی تمام شده است.»
4. گزینه‌ها:
   - حذف محصول و ادامه با سایر محصولات
   - مشاهده محصولات مشابه
   - ثبت درخواست اطلاع از موجودی (سرنخ)

### نکات کلیدی

- تمام داده‌های فرم پس از خطا حفظ می‌شوند
- پیام‌های خطا تطبیقی هستند (نه عمومی)
- مشتری هرگز احساس سرگردانی نمی‌کند
- تمام تصمیمات مطابق D-047 است

## E6: مسیر چک‌لیست اعتماد صفحه محصول (Trust Checklist Flow)

**پرسوناهای هدف:** P1, P2, P3 (مشتریان), P4, P5 (مدیران خانواده)
**ماژول‌های مرتبط:** M1 (کاتالوگ), M12 (درباره برند)
**سند مرجع:** docs/TRUST-CHECKLIST.md (D-048)

### اصل بنیادین

> اعتماد از طریق محتوا ساخته می‌شود، نه از طریق چهره.
> هر صفحه محصول باید ۵ ستون اعتماد را نمایش دهد.

### مسیر اصلی: مشاهده صفحه محصول با چک‌لیست اعتماد

1. مشتری وارد صفحه محصول می‌شود
2. عکس اصلی و نام محصول را می‌بیند
3. داستان مبدأ محصول را می‌خواند (۲-۴ جمله واقعی)
4. نشانه‌های اعتماد را نزدیک دکمه خرید می‌بیند:
   - ✓ سیاست مرجوعی شفاف
   - ✓ قیمت نهایی بدون هزینه پنهان
   - ✓ ارسال تضمین‌شده
5. اطلاعات تماس واقعی را در فوتر می‌بیند
6. نظرات مشتریان را می‌بیند (یا حالت «اولین نفر»)
7. تصمیم به خرید می‌گیرد

### مسیر فرعی: محصول بدون نظرات (ماه اول)

1. مشتری وارد صفحه محصول می‌شود
2. به جای نظرات، پیام ملایم می‌بیند:
   «اولین نفری باشید که نظر می‌دهد!»
3. توضیح: «نظرات شما به دیگران کمک می‌کند تصمیم بهتری بگیرند.»
4. مشتری احساس فشار نمی‌کند
5. پس از تحویل سفارش، لینک نظردهی برایش ارسال می‌شود

### مسیر فرعی: محصول بدون داستان مبدأ

1. ادمین محصول جدیدی اضافه می‌کند
2. داستان مبدأ را وارد نمی‌کند
3. محصول در کاتالوگ نمایش داده می‌شود
4. اما بدون برچسب «اصالت تأییدشده»
5. ادمین در داشبورد هشدار می‌بیند: «محصول بدون داستان مبدأ»
6. ادمین می‌تواند داستان را اضافه کند

### مسیر فرعی: محصول بدون عکس

1. ادمین محصول جدیدی اضافه می‌کند
2. عکس را آپلود نمی‌کند
3. محصول در کاتالوگ نمایش داده نمی‌شود
4. ادمین در داشبورد هشدار می‌بیند: «محصول بدون عکس»
5. حداقل ۱ عکس واقعی الزامی است

### نکات کلیدی

- تمام نشانه‌های اعتماد نزدیک دکمه خرید هستند
- نظرات تستی مطلقاً ممنوع است
- اطلاعات تماس واقعی و قابل کلیک است
- ساعات پاسخگویی: ۱۱ صبح تا ۷ عصر
- آدرس فقط شهر و استان است (بدون محله یا کد پستی)
