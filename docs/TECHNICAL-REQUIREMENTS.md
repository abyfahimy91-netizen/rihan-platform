## ۲. احراز هویت (Authentication) — Passwordless

### ۲.۱ مدل کلی

Passwordless موبایل‌محور + Device Remembering + Guest Checkout.
رمز عبور فقط اختیاری (در تنظیمات حساب). از روز اول فعال.

### ۲.۲ ثبت‌نام / ورود مشتری (یکپارچه)

مرحله ۱: ورود شماره موبایل (اعتبارسنجی: ۱۱ رقم، ۰۹)
مرحله ۲: کد OTP شش‌رقمی (Kavenegar Verify)
  - ۶ باکس — Auto-fill — Paste — تایمر ۹۰ ثانیه
  - حداکثر ۳ تلاش — ارسال مجدد
مرحله ۳: ورود موفق → ثبت دستگاه (Device Remembering)
  - جلسه ۳۰ روزه برای دستگاه شناخته‌شده
  - بدون OTP مجدد تا ۳۰ روز (مگر خروج دستی)

تفاوت ثبت‌نام و ورود: سیستم خودکار تشخیص می‌دهد.
  - شماره جدید = ثبت‌نام خودکار
  - شماره موجود = ورود

### ۲.۳ Device Remembering (به خاطر سپاری دستگاه)

- پس از OTP موفق، دستگاه به‌عنوان قابل‌اعتماد ثبت می‌شود
- Token بلندمدت (۳۰ روز) در HttpOnly Cookie
- ورودهای بعدی: بدون OTP — مستقیم وارد می‌شود
- انقضا: ۳۰ روز عدم فعالیت → OTP مجدد
- مدیریت: کاربر از حساب خود دستگاه‌ها را ببیند/حذف کند
- ادمین: از پنل بتواند دستگاه‌های هر کاربر را ریست کند

### ۲.۴ خرید مهمان (Guest Checkout)

- کاربر بدون حساب کاربری سفارش ثبت می‌کند
- فرم سفارش: شماره موبایل → OTP تأیید → آدرس → پرداخت
- پس از تحویل: پیامک دعوت به ساخت حساب (اختیاری)
- سفارش مهمان با شماره موبایل قابل پیگیری است
- محدودیت: حداکثر ۵ سفارش مهمان → سپس حساب لازم است

### ۲.۵ نظر مهمان (Guest Review)

- پس از تحویل: پیامک «نظر شما: rihan360.ir/review/[token]»
- کلیک → OTP سبک → فرم نظر → ثبت
- بدون نیاز به ساخت حساب
- Token یک‌بارمصرف — ۷ روز اعتبار

### ۲.۶ رمز عبور (اختیاری)

- فقط در تنظیمات حساب کاربری قابل تعریف
- برای کاربرانی که OTP نمی‌خواهند (مثلاً خارج از کشور)
- اگر تعریف شود: ورود با رمز هم ممکن است (روش جایگزین)
- Hash: bcrypt (cost=12)
- فراموشی رمز: OTP → ورود → تغییر رمز در تنظیمات

### ۲.۷ ورود ادمین (بدون تغییر)

فرم: نام کاربری + رمز عبور (بدون OTP — پنل داخلی)
قفل: ۵ بار اشتباه → ۱۵ دقیقه
جلسه: ۸ ساعته
لاگ: زمان + IP + دستگاه

### ۲.۸ ورود تأمین‌کننده

فرم: شماره موبایل + رمز عبور
دسترسی: فقط با ایجاد حساب توسط ادمین اصلی
جلسه: ۸ ساعته

### ۲.۹ پنل پیامک

ارائه‌دهنده: Kavenegar (کاوه‌نگار)
API: Verify (تولید + ارسال + اعتبارسنجی)
هزینه: ~۲۰,۰۰۰ تومان/ماه (سال اول)
مجوز: فقط کارت ملی — بدون مجوز کسب
خط: اختصاصی — نام «ریهان»
محدودیت: حداکثر ۳ OTP در ۱۰ دقیقه per شماره

### ۲.۱۰ امنیت

- HTTPS اجباری (Let's Encrypt)
- JWT در HttpOnly + Secure + SameSite Cookie
- Token دستگاه: جدا از JWT — بلندمدت — قابل ابطال
- پیام خطا: مبهم — «شماره یا کد اشتباه است»
- Rate Limit: ۳ OTP / ۱۰ دقیقه / شماره
- لاگ: هر ورود/خروج/ثبت دستگاه
- آینده: معماری آماده WebAuthn/Passkey/Biometric

## ۴. ایران‌محور

- کد پستی: ۱۰ رقم
- آدرس: استان / شهر / خیابان / پلاک / واحد

## ۵. الزامات امنیتی

### ۵.۱ لایه انتقال

- HTTPS اجباری (Let's Encrypt — رایگان — تمدید خودکار)
- HSTS Header فعال
- Redirect خودکار HTTP → HTTPS

### ۵.۲ لایه اپلیکیشن

- bcrypt (cost=12) برای hash رمز
- JWT در HttpOnly + Secure + SameSite Cookie
- CSRF Token در تمام فرم‌ها
- Rate Limiting: ۱۰۰ درخواست/دقیقه برای هر IP
- Input Validation: سمت سرور (نه فقط کلاینت)
- SQL Injection: Parameterized Queries (ORM)
- XSS: Escape خروجی + Content-Security-Policy Header

### ۵.۳ لایه داده

- پشتیبان‌گیری خودکار: روزانه (حداقل ۷ نسخه)
- رمزنگاری داده‌های حساس: شماره کارت، رسید پرداخت
- جداسازی دیتابیس از وب‌سرور (در صورت امکان)
- دسترسی دیتابیس: فقط از localhost

### ۵.۴ لایه سرور

- فایروال: فقط پورت ۸۰، ۴۴۳، ۲۲ باز
- SSH: فقط با کلید (بدون رمز)
- آپدیت امنیتی: ماهانه
- لاگ دسترسی: Nginx + اپلیکیشن
- مانیتورینگ: بررسی آپتایم هر ۵ دقیقه

### ۵.۵ لایه انسانی

- رمز ادمین: حداقل ۸ کاراکتر + تغییر هر ۹۰ روز
- دسترسی ناظر: فقط خواندن (بدون تغییر)
- لاگ فعالیت: چه کسی + چه کاری + چه زمانی + از کجا
- حذف حساب: غیرفعال‌سازی (نه حذف داده)

- پیش‌فرض: همه فعال (به‌جز ماژول‌های Should/Could)

## ۸. استقرار (Deployment)
